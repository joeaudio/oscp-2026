# 10 — Active Directory enumeration and authentication

**Outcome:** turn a starting credential into a map of users, groups, SPNs,
shares, sessions and object permissions. Use only an authorized domain lab.

## Tutorial

Active Directory stores identities and access relationships. A domain
controller (DC) authenticates users and serves directory data. Kerberos uses
tickets; NTLM uses challenge-response. A service principal name (SPN) maps a
service to an account and can be relevant to service-ticket analysis.

With a supplied domain account on a Windows lab host:

```cmd
whoami /all
net user /domain
net group "Domain Admins" /domain
nltest /dclist:training.local
```

If the AD PowerShell module is present:

```powershell
Get-ADUser -Filter * -Properties ServicePrincipalName |
  Select-Object SamAccountName,ServicePrincipalName
Get-ADComputer -Filter * | Select-Object Name,DNSHostName
```

Collection tools such as SharpHound/BloodHound can help map relationships in
course labs; confirm collector version and scope. A graph edge is a lead,
not proof that a login or execution path works. Record every credential's
source and permitted use privately, never in public notes.

Authentication attack paths depend on exact preconditions. Kerberoasting
requests a ticket for an SPN account and may permit offline password testing.
AS-REP roasting needs a particular account setting. Password spraying is an
online attack with lockout risk. Do not run any of these against a domain
without explicit authorization and a rate plan.
